# 后端开发工程师

## 岗位JD
- 负责核心业务服务的设计、开发与维护，确保接口稳定、性能可靠、易于扩展。
- 参与数据库表结构设计、缓存策略设计、消息链路治理和服务拆分演进。
- 与前端、产品、测试协作，推动需求按期上线，并在上线后持续跟进质量和业务效果。
- 面向真实线上环境处理高并发、慢查询、缓存失效、消息堆积、依赖抖动等问题。

## 必备技能
- 熟悉至少一门后端主语言，通常是 Java、Go 或 Python，能独立完成业务接口设计与实现。
- 掌握 SQL、事务、一致性、索引优化等数据库基础，能定位常见性能瓶颈。
- 理解 Redis、消息队列、定时任务、日志与监控在业务系统中的使用方式。
- 能从工程角度说明接口幂等、灰度发布、回滚策略、链路追踪和故障复盘。
- 具备一定系统设计意识，能结合流量、数据量、稳定性和开发效率做方案权衡。

## 常见面试题
1. 请挑一个你最熟悉的后端项目，说明系统背景、你的职责、核心指标以及你真正负责的模块。
2. 你做过哪些数据库或缓存优化？为什么会遇到这个问题，你如何定位，效果如何验证？
3. 如果某个核心接口在高峰期 RT 飙升，你会如何排查？请讲清楚排查路径和证据链。
4. 你在项目里做过哪些技术取舍，例如同步改异步、读写分离、缓存旁路、表结构重构？
5. 如果线上发生消息重复消费、库存不一致或接口幂等问题，你会如何处理和复盘？

## 重点考察维度
- 是否能把项目讲清楚，不只是描述背景，还能说明个人贡献、关键动作和业务结果。
- 是否理解后端工程常见问题的底层原因，例如慢查询、缓存击穿、数据不一致、流量抖动。
- 是否具备方案取舍能力，能说明为什么选当前方案、放弃了哪些方案、代价是什么。
- 是否具备线上意识，能描述监控、告警、定位、缓解、复盘的完整链路。
- 是否能把技术动作和业务结果关联起来，例如性能提升、故障减少、研发效率改进。
