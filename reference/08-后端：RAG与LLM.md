# 08 RAG 与 LLM：增强能力，也限定承诺

## 1. 先区分两类上下文

用户简历和 JD 描述本人的经历与目标岗位；岗位知识库提供通用技能、题型与评价参考。知识库不是候选人能力证明，不能因为检索到“Redis 原子性”就替候选人补出正确回答。

当前 RAG 只服务 Planning，不直接进入 Interview 或 Evaluation。这个边界降低每轮回答的检索开销，也意味着对话阶段不会自动检索最新答案来核实候选人每句话。

## 2. 离线索引与在线检索

离线流程由 indexer 等模块把知识文件解析、分块、附带岗位和文档类型元数据，再生成向量并写入 Milvus Lite。在线根据岗位、技术语言、难度、简历亮点和技能构造查询，检索岗位范围内的片段，按 jd、skills、questions、rubric 分组打包为规划上下文。

当前查询只取有限简历摘要，打包内容上限为 3200 字符，默认 top_k 为 4。这些是实现参数，不是已经通过实验找到的最优值。它们会在相关性、信息覆盖、Prompt 长度之间形成取舍。

RAG 默认关闭；岗位归一化失败则跳过；检索异常返回退化上下文，主规划可继续。是否命中、命中了哪些来源，应通过检索日志确认，不能只看开关为 true。

## 3. 默认 embedding 的真实能力

local 模式把分词后的 token 哈希到固定维度，累加带符号权重并归一化。这种方法确定、便宜、离线可运行，但对不同措辞和深层语义的理解有限，也会发生哈希碰撞。

因此“用了向量检索”不能自动变成“理解了岗位语义”。OpenAI embedding 是另一条可配置路径；切换模型、维度或分块方式后，应重建索引并用固定查询检查召回。配置里声明维度也不能替代检查实际返回向量长度。

教学例子：查询使用“库存扣减”，知识文件写“存货预占”。默认哈希方式可能难以建立联系。要判断是否值得改用语义 embedding，应比较这些同义表达上的检索结果，而不只是展示一个命中截图。

## 4. Planning 输出为什么需要多层校验

模型返回合法 JSON 只解决语法问题。业务还要求主题数量、字段、唯一 ID、必考维度、时间预算和候选人摘要边界。

当前计划规范化处理 4—5 个主题、至少 4 个必考主题，检查校招／社招维度，调整时间预算，并防止候选人摘要泄露完整 opening_question。偶发超量主题有裁剪处理，不能概括为“任何不合格都整轮重试”。

Agent 最多尝试三次，校验反馈进入下一次提示词；失败后构建模板计划并标记来源、尝试次数和降级原因。重生成还要求符合策略、与旧版有有效差异。这样能够识别“格式正确但调整没有生效”。

注意：输出校验可以检查字段和规则，但不能充分证明主题贴合简历或问题具备高质量。后者仍需样本评估。

## 5. 降级矩阵

| 环节 | 常见降级行为 | 没有保证的内容 |
|---|---|---|
| 岗位检索 | 返回空或默认岗位上下文 | 不能保证获得相关知识 |
| 计划生成 | 重试后模板计划 | 个性化深度可能下降 |
| 证据抽取 | 空增量，保留旧记忆 | 本轮回答不自动获得证据 |
| 动作决策 | 规则决策 | 不等价于高质量语义判断 |
| 话术生成 | 模板问题 | 连贯性和具体性可能下降 |
| 报告生成 | 规则报告或最小报告 | 不能把缺证据包装成可信结论 |

这些描述主要针对各层捕获的生成、解析或校验异常，不承诺所有初始化错误都在同一保护范围内。移除产品 mock 模式与测试中使用 fake 并不冲突：前者定义真实产品主路径，后者隔离外部依赖。

## 6. SSE 怎样工作

回复路由先等待 reply_to_interview 完成，再返回 StreamingResponse。流内依次发送 session_state、progress、message_start、delta、message_end、done。delta 来自已生成完整文本的切块，不是模型 token。

因此等待可拆成：请求校验与读取 + 图中各项计算 + 持久化 + 分块展示。前端打字快慢只改变最后一项。若要改善开始等待，先测抽取、决策、话术等阶段，不能把 chunk_size 调小当成模型提速。

流开始后异常可用 error 事件表达；流开始前的业务失败仍是 HTTP 错误。这两类失败需要分别处理。当前没有仅凭 SSE 就获得断点续传、取消模型计算或可靠消息队列的能力。

## 6.5 v2.2 算法 judge：JSON 强约束 + 兜底

`algorithm_judge_service.judge_submission()` 在 prompt 中约束"Return JSON only"，但仍做三层鲁棒：

1. markdown 围栏剥离（` ```json ... ``` `）
2. 第一个 `{` 起 + 平衡括号匹配截取
3. `json.loads` 解析失败时返回 `verdict=unparsed`，所有分项 0，feedback 提示重试，**不抛 5xx**

评分归一化：所有分项 + overall 都钳制到 [1, 5]；不接收 0/负分/超过 5 的输出。

这与正常规划生成降级矩阵不同：算法 judge 不会回退到"模板"或"规则决策"，因为没有等价的本地实现，只能重试或提示用户重写。

## 7. 怎样验证模型与检索质量

建议准备脱敏固定样本：不同岗位、简历长短、无 JD、JD 冲突、回答跑题、技术错误、矛盾回答。记录计划相关性、必考覆盖、无效输出、抽取漏检与误检、追问是否针对缺口，以及各阶段耗时和调用次数。

比较 RAG 开关或模型版本时保持样本和评价口径一致。缺少基准时，只能说明链路运行与规则通过，不能报告“质量提升百分之多少”。此处是建议方法，本次未执行外部模型评测。
