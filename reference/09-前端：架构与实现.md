# 09 前端架构：展示、缓存与服务端事实

## 1. 页面如何对应面试过程

App 使用 React Router 组织简历、配置、计划、正式面试、评估和记录页面。每个页面有对应 services、types 与 hooks。不要沿用旧笔记中“所有页面仍堆在一个 App.tsx”的当前架构描述。

页面负责渲染和交互；services 负责 HTTP；hooks 管理查询、mutation 和缓存；types 描述接口结构；utils 处理打字、评分展示和练习卡片等转换。

这种拆分让页面不必直接处理每个请求细节，但类型定义不会在运行时自动验证服务端数据。API 契约变化仍需联调。

## 2. 服务端数据与临时交互分开

会话详情、计划版本、报告属于服务端事实，放在查询缓存中；输入框、弹窗和当前打字片段属于本地交互。若把两者混在一个大对象里，刷新、重试与流事件很容易互相覆盖。

useInterviewLive 的查询键包含 sessionId，避免不同会话共用同一个缓存条目。查询在处理回复时约每 2 秒刷新，active 常态约每 15 秒刷新，并在窗口重新聚焦时重新读取。轮询是状态对齐手段，不代表模型每两秒产生一个结果。

## 3. 一次发送怎样呈现

用户提交回答后，页面应显示处理中、限制重复操作；services 通过 fetch POST 发送答案与 Bearer token；解析 SSE 事件，将 delta 交给展示逻辑；完整消息结束或重新查询后，以服务端持久消息对齐最终结果。

当前接口在完整计算后才开始发送流，因此“处理中”的反馈很重要。不能把尚未收到 delta 当成连接必然失效，也不能把 message_start 当成模型刚开始思考。

## 4. SSE 解析为何需要缓冲

网络读取的一块字节不对应一个业务事件。一个事件可能被拆成多次读取，多个事件也可能合在一次读取。client.ts 使用 TextDecoder 流式解码并保留 buffer，再按空行切分事件，避免中文 UTF-8 字节分割与半包直接解析。

当前解析器针对后端约定的 event 与单行 data 格式，不是完整通用 SSE 实现。多行 data、不同换行方式、尾部未终止事件等情况，若协议扩展需要增加针对性验证。不能因为使用了 TextDecoder 就宣称所有边界都覆盖。

## 5. 请求失败后怎样判断

HTTP 失败发生在流建立前，使用普通错误响应；流过程中还可能收到 error 事件；连接直接中断则未必有业务错误事件。前端必须避免把三者都呈现成"回答没有保存，请重发"。

教学情境：后端已落库但浏览器断网，用户重连后应该先读会话。如果助手消息已经存在，就恢复展示；若显示处理中，继续观察；若只存了用户消息且处理失败，应根据明确重试语义处理。`(session_id, request_id)` 唯一约束 + 按 seq 配对支撑幂等 retry，但**不**承诺跨进程 worker 一定不重复。

401 由 `services/client.ts` 的 `unauthorizedHandler` 统一处理（清 token + 写 `offer-agent-return-path` + 跳 `/`）；非 401 错误保留登录态。`App.tsx` 在 catch 块不再做 `isAuthError` 推断 — 那条路径已不可能执行。`requestJson` / `requestFormData` 默认 `keepalive: true`，防止页面/tab 关闭时未完成的请求被 abort。

## 6. 倒计时与评分展示

后端维护截止时间与结束时剩余时间快照。浏览器倒计时是展示，用户修改系统时间或刷新不应成为业务结束的唯一依据。面试结束后还在持续减少的倒计时会让报告像仍在进行，冻结快照用于避免这种误导。

`deadline_at` 由 `configuration.duration_minutes`（15/30/45/60）决定；离开页面通过 `pause` / `resume` 接口冻结计时，`_compute_remaining_seconds()` 跳过暂停区间。

评分展示要区分 null 与零分、部分评分覆盖与完整考察、验证状态与表现高低。`degraded` 评估降级时前端顶部展示 `<DegradedBanner>`；`evaluation.degraded=true` + `degraded_reason` + `degraded_message` 由后端评估主路径失败时显式返回，不静默 fallback 到极简模板。练习卡片来自不同报告结构，统一转换应避免重复或矛盾文案，而不是在页面里随意拼接。

## 7. 语言切换与登录页卖点

`<LanguageSwitcher>` 是侧栏品牌区下方的高对比度 Pill 按钮（gradient 背景 + 边框 + box-shadow + 国旗 emoji），让"切换语言"成为第一眼就能看到的入口。点击直接调 `i18n.changeLanguage`，写 `localStorage['offer-agent-locale']`，**不**写后端 — 切语言是纯客户端行为。i18n 词条覆盖 8 个 namespace × 2 语言（auth / billing / common / errors / evaluation / interview / plans / records / resumes / sidebar），i18next 同步初始化后再 `createRoot`，避免首屏闪。`useLocale` 读 `document.documentElement.lang` 供 `Intl.*` 使用；`formatDateTime` / `toLocaleString` 显式 `timeZone: 'Asia/Shanghai'`。

`<AuthPage>` 加 `leadingSlot` 槽位，App 在 login/register 路由渲染时插入 `<SellingHighlights compact />`：3 张卖点卡片（基于 3000+ 真实面试数据 / 计划→执行→证据三段式 / 评分可追溯），让用户进入登录页就能看到差异点。`<ResumesPage>` hero 区下方放完整版（`compact={false}`）3 列卡片。

## 8. 充值面板与算法回合侧栏

侧栏 `<AppSidebar>` 的 `quota_label` 旁加 "+" 按钮，点击触发 `<BillingPanel>`（半透明 modal + 2 张档位卡片：¥20/5 次 vs ¥200/月卡）。`onRecharged` 通知父组件通过 `useBillingRecharge` 调 `getMe(token)` 重新拉取权威 user profile，**不**本地合并；侧栏在 `user.quota_remaining === null`（订阅有效）时显示 "Unlimited" + ⚡，否则显示数字。

`<BillingPanel>` 走真实 Stripe Checkout 流程：调 `createOrder` 拿 `checkout_url`，`window.location` 跳到 Stripe 收银台；webhook 完成后下次轮询 / 重新进入 App 时会拉到最新 user。`/billing/return` 落地页轮询订单状态。

`<InterviewLivePage>` 当 `configuration.include_algorithm=true` 时，头部"Algorithm Round"按钮可见；点击打开右侧 side panel（`app-algo-panel`）承载 `<AlgorithmTurn>`。算法回合不写 messages 表，仅 React state 内展示评分。`useInterviewLiveState` 封装全部状态机/事件流/计时器，5 个子组件（`InterviewLiveHeader` / `InterviewLiveStartCard` / `InterviewLiveTopicBar` / `InterviewLiveChat` / `InterviewLiveComposer`）按职责拆分。

## 9. 已登录态 ReleaseLog

`<ReleaseLog>` 是已登录产品内 changelog（区别于公开访客 `<LiveUpdates>`）：标题 + 多条 release 按日期倒序；每行日期（MM.DD + 年份）、模块（i18n label）、版本号、单行 headline；展开后展示 1-3 条变更要点（i18n bullet）；列表带 `max-height` + 自定义滚动条（webkit + firefox）；第一条默认展开。

集成到 `<ResumesPage>`：从「ResumesPage 下方」改为 2 列布局的右侧 320px 侧边栏（`position: sticky; top: 16px` 跟随滚动，最大高度 `calc(100vh - 220px)` 自带滚动条），主区 + 侧栏。`common.json` 含 `release_log_*` / `release_v2*_*` 等 i18n key。

## 10. 简历 processing-id reconcile

`<useResumes>` 简历上传后处理是异步流程：返回 `processing_id` 后端继续解析。`sessionStorage` 持久化 processing id，页面 mount 时调 `getResume(id)` reconcile — 如果后端已经处理完，把 processing 状态转成 normal；如果还在 processing，继续轮询或重试。`App.tsx` 不再直接操作 `localStorage`，统一走 `useResumes` 提供的存储抽象。

## 11. 验证重点

至少演练刷新计划页、重复点击开始、提交后切换页面、流中断、报告空分、学习对比没有历史场次、失效登录和窄屏长文本。前端 build 验证类型和打包，不能代替交互验证。

`vite build` 当前会警告 `index.js` 638 kB > 500 kB 阈值（路由级 code splitting 留作后续）；样式上以 `app-*` 为统一 class 前缀（替代早期的 `v2-*`），避免与 shadcn 私有变量混淆。`AlertDialogAction` / `AlertDialogCancel` 用 `buttonVariants + AlertDialogPrimitive.Action/Cancel`，不嵌套 `<Button asChild>`，防止 data-slot 冲突 / ref warning。`InterviewEvaluationPage` 空态（`!report`）暴露 retry 按钮 + back 按钮。
