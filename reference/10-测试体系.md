# 10 测试体系：区分流程正确与模型质量

## 1. 首先说明测试能够证明什么

测试至少分三层：确定性业务规则、接口与持久化协作、真实模型语义质量。前两层可以隔离外部模型稳定运行；第三层需要固定样本、人工标准和多次比较。

“测试通过”不等于“面试官问得好”。反过来，真实模型能完成一场演示，也不能证明状态机、权限与重复提交没有缺陷。本章列出仓库已有测试与建议补充，不虚构执行结果。

## 2. 仓库现有 fake 的作用

conftest 提供自动 fixture，默认把模型替换为失败客户端，验证规则和模板降级。部分测试再通过 monkeypatch 注入特定结构化结果，检查正常路径的数据处理。

产品删除 mock 模式并不禁止测试 fake。测试替身用于控制输入、制造故障和避免真实费用，不能当成真实模型语义能力的证据。也不要声称全套测试只测试降级，具体文件可能覆盖注入结果的成功分支。

## 3. 已有测试如何对应风险

| 风险 | 代表测试文件（backend/tests 下） | 主要阅读目标 |
|---|---|---|
| 计划形状和维度不合格 | test_planning_validator.py | 校验与规范化边界 |
| 重生成没有实际变化 | test_regeneration_validator.py | 策略与有效差异 |
| 模型动作越界 | test_interview_actions.py | 动作归一化 |
| 时间、轮数、重复回复 | test_interview_agent_step4_step5.py | 强制结束与常见重复保护 |
| 证据原话编造或计划外信号 | test_interview_memory_step2.py | 抽取校验、合并、投影 |
| 负面回答仍拿到中分 | test_interview_evaluation_scoring_calibration.py | 负向惩罚与正向证据区分 |
| 引用无法对应回答 | test_interview_evaluation_evidence_references.py | 引用定位 |
| 不合格场次污染档案 | test_learning_eligibility.py | 有效性过滤 |
| 跨场结果解释不正确 | test_learning_session_comparison.py | 可比数据与展示 |

测试名表达作者意图，具体断言才决定证明范围。例如 duplicate_reply_rejected 验证预先设置处理中状态后的拒绝，不应自动推广为真正两个并发请求的正确性。

## 4. 怎样设计有意义的确定性测试

从不变量出发：计划确认后引用同一版本；未验证项分数为空；抽取失败保留旧证据；非法动作不能跨主题；结束时间展示不再变化。

尽量构造最小状态，不依赖整场长对话。例如原话校验测试只需一条最新回答、一项合法信号、一条不存在的引语；合并测试只需旧证据和空增量。这样失败时能定位规则，而不是被大量上下文掩盖。

边界测试要覆盖等于阈值、阈值前后、多个条件同时成立，以及时间可控输入。对于 12 轮上限，还应检查触发轮回答是否进入证据路径，这比只断言 status=evaluating 更能暴露业务缺口。

## 5. 故障注入比成功演示更重要

建议增加或补强这些场景：确认两个更新之间失败；额度已扣而开场未成功；用户消息已写入而图失败；助手消息已写入而运行态更新失败；评估已保存而学习档案写入失败；两个请求同时激活或回答。

验证时分别检查状态、消息数、额度、版本、报告和重试后结果，不能只检查 HTTP 状态码。并发测试需要真正同步起跑与独立连接，预置一个布尔锁只覆盖顺序路径。

这些是建议测试，除非实际新增并运行，否则不能写进已完成覆盖清单。

## 6. 真实模型质量怎样测

准备匿名固定样本，每条明确期望：哪些原话支持哪些信号、哪些说法应视为风险、哪些内容仍不足。对抽取计算漏检与误检，对追问评判是否针对缺口，对评分比较人工标注和规则输出的分歧。

同时记录 Provider、模型版本、Prompt 版本、样本版本、RAG 配置、调用次数和阶段耗时。模型有随机性，不能凭一次截图宣布改进有效。对于不同难度与不同主题，分别分析分歧，而不是只给一个总平均值。

## 7. 本地执行与证据留存

在 WSL 项目环境中，后端可以使用虚拟环境运行 `pytest`；先运行与改动相关的文件，再按需要运行全套。前端 `npm run build` 检查 TypeScript 和构建，`npm run lint` 做静态检查。不要向真实模型发请求来替代确定性单测。

本次文档重写未运行应用测试或真实模型评测，避免把文档核对描述为运行验收。维护笔记时应记录实际命令、环境、通过／失败摘要与未验证范围。若后续修复业务代码，必须为新行为做相应验证。
