# 12 面试追问训练：从结论讲到机制，再讲边界

使用方式：先不看提示口述，再按追问继续回答。这里提供解释骨架，不建议背成固定话术。个人负责范围、真实故障和效果数据必须来自自己的实践。章节号对应 README 中的专题。

## 1. 这个项目做什么，核心难点是什么

起答：覆盖简历解析、计划确认、动态面试和证据报告，重点是让多轮模型行为受业务边界约束。

继续追问：为什么普通聊天做不好？因为自然语言合理不代表考察目标一致、状态可靠、评估有依据。为什么要计划？为了连接生成、执行与评估。为什么用户要确认？让方向在开始前可见并可调整。能否保证问题都好？不能，规则限制结构，语义质量还需要样本评价。

应能举库存案例，解释“问 Redis 常识”和“验证库存项目中的贡献与取舍”的区别。见 00—02。

## 2. 你个人做了什么

起答应包含明确模块、边界与可展示成果，例如亲自完成的接口、改造、测试或排查。代码库里存在某功能不能证明是自己完成的。

继续追问：哪一部分是参考或 AI 协助？你怎样审查生成内容？你能从零还原关键路径吗？你验证过什么？可以回答真实工具使用和验证过程，不需要虚构全手写经历。准备一次自己能现场复现的修复，比背一段庞大的“独立完成全部功能”更可信。见 13、15。

## 3. 为什么拆三个 Agent，是不是过度设计

起答：规划、执行和评估关注不同输入输出，用统一确认计划连接，拆分便于校验、测试和独立降级。

继续追问：它们自主协商吗？当前由服务层直接调用。独立部署吗？不是。为什么不能普通函数？可以，Agent 命名不带来额外可靠性，价值在边界与协议。拆分代价？调用链、协议维护和时延。怎样证明值得？比较定位问题的难度、规则覆盖与模型调用成本。见 03—05。

## 4. 为什么用 LangGraph，持久化是谁做的

起答：单轮有共享状态和条件分支，图表达使流程集中可见。

继续追问：V1 用过吗？历史 cabf03b 已经使用。断电从某节点继续吗？当前没有明确 checkpointer，跨轮由服务层加载和保存运行态。怎样增强恢复？任务记录、版本、可重放输入和明确提交边界。见 04、05。

## 5. 计划为什么锁定，怎样锁定

起答：确认后固定 confirmed_plan_id，避免问答与评分基准漂移。

继续追问：生成时就锁了吗？没有，确认前可以新建版本。用户能看到完整题干吗？预览与内部计划分开。重复确认呢？返回冲突。两个确认同时到达呢？当前多步骤操作没有充分原子保证。如何修复？事务、条件更新、唯一约束及预期版本。若中途改计划呢？需要计划修订与证据版本归属，不能只更新一个 JSON。见 02、04、07。

## 6. 一轮回答准确经过哪些步骤

起答必须说出：状态检查与处理标记 → 原话保存 → ingest 增计数 → Observe → 边界 → 正常路径抽取与合并 → Decide 归一化 → Act 或推进 → 保存消息与运行态 → SSE。

继续追问：边界在哪里？抽取之前。第 12 轮呢？本轮计数增加后触发结束，可能跳过抽取。原话是否丢失？服务层已保存。怎么改？保留停止决策边界，同时确保终止轮证据处理，考虑超时预算和补偿任务。见 05。

## 7. 模型输出非法动作怎么办

起答：normalize_decision 限制动作集合、主题目标和切题标志。

继续追问：模型想跳第三主题呢？目标被约束到当前主题，推进由代码决定。还有题却要 finish 呢？转 next_topic。重复追问如何判断？比较期望信息首项与上次字符串。换一种说法呢？当前不能保证语义去重，可用稳定信号 ID 改进。见 05、07。

## 8. 三层记忆与聊天历史有什么不同

起答：近期消息保留语境，工作记忆保留结构化证据与缺口，长期档案跨场汇总，主题摘要辅助压缩。

继续追问：都是向量检索吗？不是。裁剪按 token 吗？当前按消息数和字符。所有节点都统一裁剪吗？需要逐调用核对，不能一概而论。摘要丢信息怎么办？保留原始消息用于追溯，不能把摘要当成全部事实。见 05、06。

## 9. 怎样避免证据幻觉

起答：验证 quote 来自最新回答，关联合法主题与计划信号，再增量合并。

继续追问：真引语就是真判断吗？不一定，极性、信号归类和技术解释仍可能错。抽取失败呢？空增量保留旧记忆，本轮不自动验证。用户说谎能识别吗？只能发现部分矛盾与信息缺口，不能验证现实经历真实性。见 06。

## 10. 分数怎样算，为什么未验证不给零

起答：规则按证据与覆盖推导 1—5 分，未验证为 null，总分只平均非空项并换算百分制。

继续追问：两个主题 3、4，另两个空分，总分？70，但覆盖不完整。verified 就是高水平吗？首先表达验证覆盖，负向证据仍影响表现。0.8 置信度是 80% 正确吗？不是，是未校准启发式。相同对话一定相同分吗？固定证据输入的规则可重复，模型抽取仍可能变化。怎样校准？人工标注、固定样本、多次抽取与分歧分析。见 06、10。

## 11. RAG 在哪里使用，是否必要

起答：默认可选，仅 Planning 补充岗位材料。

继续追问：每轮都检索答案吗？没有。默认 embedding 是什么？确定性哈希向量，不是训练语义模型。无命中怎么办？继续规划。如何证明有效？对固定岗位样本比较召回与计划相关性。换模型为什么要重建索引？文档与查询向量必须采用兼容空间和维度。见 08。

## 12. SSE 是否降低模型等待时间

起答：当前先完整计算与落库，再分块输出，改善展示节奏。

继续追问：为什么开始时还很慢？抽取、决策、话术等可能串行。能并行吗？有数据依赖，不能随意并行。断流后重发吗？先查询后端结果。如何实现真实流？接入 Provider 流式接口，同时处理部分结果校验、取消、持久化与失败语义。见 08、09、11。

## 13. 重复点击和并发怎样处理

起答：前端限制操作，后端检查状态和 reply_in_progress，部分接口返回已有结果。

继续追问：两请求同时读取空标记呢？存在竞态。SQLite 自带事务是否足够？多个方法独立提交，业务不自动原子。如何修复？条件更新获得处理权、state_version、幂等请求 ID、短事务提交。额度扣减也要保护，不能只修回复。见 07。

## 14. 你遇到过什么困难，怎样定位

必须选真实做过的事件。若只读到代码风险，应明确说是审查发现或故障推演。

追问链：用户症状 → 哪些功能受影响 → 有哪些假设 → 哪份日志或数据排除了哪个假设 → 根因在哪个边界 → 为什么选择该修复 → 怎样验证 → 是否有副作用 → 还能怎样改进。

不要用“模型不稳定，加了重试”结束。需要说明是解析失败、schema 不符、语义不符还是服务不可用，不同根因不能用无限重试解决。见 15。

## 15. 怎样测试，fake 能证明什么

起答：规则单测、接口与持久化集成、真实模型质量评估分开。

继续追问：测试默认失败模型怎么测成功分支？注入可控结构化结果。能证明语义好吗？不能。测并发了吗？不能用顺序锁测试替代。覆盖率高为什么还会漏？跨操作提交与业务不变量可能没进入断言。见 10。

## 16. 上线过吗，怎样部署与回滚

按真实情况回答。本仓库具备本地启动材料，本次没有核实正式生产上线。

继续追问：Docker 配置在哪？当前没有。数据放哪？SQLite 与可选索引需持久路径。环境变量一定覆盖吗？当前 Settings 省略普通环境源。健康正常代表模型正常吗？不代表。回滚代码即可吗？还要考虑 schema 与 JSON 兼容。容量多少？没有实测不报数字。见 11。

## 17. 跨场学习是否真的闭环

起答：已完成结果写单场快照并按四项上下文聚合，提供部分建议与对比能力。

继续追问：结束就一定记档案吗？要有有效讨论等条件。重复评估会重复算一场吗？outcome 按 session_id 管理。长期记忆会自动改变 Planning 吗？当前不能由 hints 文件存在就推断自动注入。两场分数能直接比吗？计划、难度与覆盖差异影响可比性。见 06。

## 18. 如果继续做，先改什么

优先级应有理由：先保障不丢回答与证据、并发与重试不重复，再度量等待与模型质量，最后按数据决定检索和扩容。可以选择不同顺序，但要解释用户影响、实现代价和验收标准。

最终训练：随机选择上述任一问题，连续回答五次“具体怎样做／为什么／失败会怎样／怎么验证”。能在边界处坦率停下并给出验证办法，比没有依据地回答所有问题更可信。
