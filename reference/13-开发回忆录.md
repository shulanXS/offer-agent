# 13 开发回忆录：依据实现重建开发过程

本章是开发推演，不冒充真实日记。它给出一种符合依赖关系的实现顺序，帮助你模拟自己从空项目做起。可核实的历史差异见第 00、14 章；个人工期、内测、事故和分工需要真实材料补充。

## 阶段一：定义最小闭环

起点只有产品目标：用户提交材料后完成一次问答并得到反馈。先把用户身份、简历、会话、消息和报告之间的关系画出来，决定哪些数据刷新后必须还在。

优先交付一个固定问题驱动的最小流程。这个阶段不追求复杂智能，验收是能创建、回答、结束并重新读取。先做通路能让后续模型问题与 HTTP、数据库、页面问题分开。

可以产生的开发材料：需求边界、一条正常时序、一份最小数据字典、一份可重复的联调记录。没有这些材料，也可以通过实际补做演练建立自己的理解。

## 阶段二：接入简历和模型

先验证文件能提取文本，再验证结构化解析。PDF 只有扫描图片时，文本提取可能不足；不要把“支持 PDF”理解为已经提供 OCR。

把 Provider 调用封装在工厂，明确失败与空输出如何呈现。先用可控响应验证数据流，再用脱敏简历联调真实模型。重点区分格式错误和内容不合适，避免把所有异常都归为“Prompt 不够好”。

阶段验收：支持格式可上传、过短文本有明确反馈、简历归属正确、结构化字段与原文可核对。真实模型调用的配置、耗时与结果需要另记，不把测试 fake 当成成功接入证据。

## 阶段三：建立可持久的固定问答流程

当前 Git 旧版显示 follow_up_done 控制一次追问，可作为理解起点。保存每道题与对应消息，回答后切到下一题，最后形成报告。

为什么先固定？因为它缩小状态空间，使页面跳转、消息顺序和报告读取先有确定行为。其代价是策略不灵活，之后可以通过回放不同回答观察哪些信息没被问到。

阶段验收：刷新能恢复、消息顺序稳定、不会串用户会话、结束不再接受普通回答。此时即便模型话术自然，也不应宣称已有高质量动态决策。

## 阶段四：先引入计划契约，再引入动态策略

把隐含题单升级成结构化主题计划，加入考察目标、信号、时间预算与标准。实现预览、重生成和确认引用。先解决“全场围绕什么考”，再解决“当前该怎么追问”。

实现顺序可为：schema 与校验 → 模板计划 → 模型生成重试 → 计划落库与版本 → 预览 → 确认 → 激活读取固定版本。模板先行是开发方法，不表示当前产品以 mock 为主路径。

阶段验收：校招／社招维度合法；重生成有有效变化；确认后不能继续调整；执行读取确认版本。另补并发确认与激活的检查，避免把顺序测试当成全部可靠性。

## 阶段五：拆分单轮工作流

先把状态转换、硬边界与允许动作做成可控规则，再添加 Decide 与 Act。图负责表达节点关系，模型负责局部语义判断。对同一回答注入不同动作，观察切题、追问和结束是否都能落库并恢复。

这一阶段的典型权衡是：更清晰的解释与降级边界，会增加调用与协议。应记录各节点耗时，而不是凭感觉评价“架构更先进”。

阶段验收：非法动作不能越界，模型不能绕过轮数限制，重复信息有保护，话术失败可降级。检查第 12 轮等边界回答的数据命运，当前图顺序暴露的遗漏值得单独记录。

## 阶段六：引入证据与工作记忆

如果只让模型决定追问，仍然难以解释它依据了什么。把回答转成结构化增量：说法、原话证据、缺口、风险与矛盾。先严格校验，再合并；不要让模型每轮重写全场事实。

从库存案例开始，人工标出每句话支持的信号，再比较抽取结果。先测“原话存在、信号合法、失败不清空旧数据”，再评价“抽得是否准确”。

阶段验收：本轮抽取失败能继续，但界定信息不足；旧证据不丢；缺口随有效证据减少；持久消息仍可追溯。新增调用的延迟与成本也要记录。

## 阶段七：用证据构建报告

先确定规则评分与空分语义，再生成用户可读解释。不要一开始就追求长评语。给出全正向、全负向、部分覆盖、无证据和矛盾样本，观察评分是否符合定义。

报告再增加逐题复盘、JD 对应和练习建议。每项都应回到本场证据，避免把岗位知识当作候选人说过的话。之后加入学习快照与档案，明确哪些场次可计入，以及跨场对比的限制。

阶段验收：分数与文字不冲突、引用能定位、空分明确、重复写档案不增加场次数。规则稳定后仍需要人工校准，不能把“可复现”写成“客观准确”。

## 阶段八：联调、故障演练与部署准备

从零启动环境，运行固定脱敏闭环；在回答后刷新、断开连接、制造抽取失败和报告失败，检查数据库与页面。修复时记录症状、证据、根因、方案、验证与副作用。

部署前检查配置来源、密钥、持久化路径、代理等待与缓冲、备份恢复和迁移兼容。仓库没有 Docker 配置或真实容量数据时，先形成具体方案并验证，再将其写入已完成经历。

## 怎样转成你自己的可信经历

按第 15 章亲手完成至少一次完整闭环、一次故障定位、一次边界分析和一次设计改进验证。记录真实日期、命令、现象与结果。这样你可以说“我验证了什么、发现了什么、为什么这样修”，而不是复述别人的假想事故。

当面试官问开发过程时，用阶段的依赖关系组织叙述；问个人工作时，只陈述自己做过的部分；问未完成能力时，讲清方案与验收，不把推演说成既成事实。
