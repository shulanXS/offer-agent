核对基线：当前工作区，HEAD `5e7bafd`。源码核对日期：2026-10-15。工作区已有其他改动，本次只整理 reference。代码可能继续变化，遇到冲突以实现及验证结果为准。

## 四种内容的含义

- **实现事实**：能在当前代码中核对；不等于已经在线上压测或真实使用中验证。
- **历史事实**：能在具体 Git 版本中核对；提交日期不等于功能实际开发起止日期。
- **教学案例／开发推演**：用于理解、演练和重建开发顺序，不能直接当作亲历事件。
- **改进建议**：当前缺口的处理思路，不能写成已实现成果。

贯穿案例是教学案例：一名准备后端岗位的候选人，简历提到用 Redis 做库存扣减，JD 关注并发、一致性和个人贡献。示例里的回答、计划主题、故障均为解释机制而构造，不代表真实用户记录。

## 学会的标准

能够用五分钟说清产品闭环，用十五分钟白板还原一次回答处理；能够区分“记录了回答”“抽取了证据”“验证了能力”；能够解释模型故障、刷新、重复提交、超时和评估失败时的行为；能够坦率说出当前并发、评分校准和部署方面的不足。

`archived/` 只作为旧材料留存，不作为当前学习入口。它包含不同阶段的设想和旧实现，引用前必须重新核对。不要把多份旧文档的说法拼成一段未经核实的开发经历。
