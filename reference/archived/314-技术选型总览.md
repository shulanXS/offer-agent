# 技术选型总览

目录路径：实战项目 / AI面试智能体 / 技术选型决策 / 技术选型总览

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/MipGw9KWKiDmhjkkrSCc5e6jnlJ)

本项目技术选型分为前端与后端两部分。前端采用 React + TypeScript + Vite 技术栈，这套经典组合在刷题猫、HarnessPRD中已有详细讲解，本文不再赘述。

后端所使用的多数技术，也均在往期项目实战中落地应用：基于 FastAPI + uvicorn 搭建服务，既能适配常规 HTTP 接口，也能无缝对接各类 AI 生态；身份认证采用 JWT 方案，借助 PyJWT 与 bcrypt 实现密码哈希处理；同时还集成了 SSE 流式输出能力。

通用选型参考文档：[技术选型分析](https://acn2lw4rwc26.feishu.cn/wiki/MyGQw0dwQiuXgkkIniDcahJdnzg?fromScene=spaceOverview)

本项目技术栈汇总：

| 层次 | 用了什么 | 一句话说明 |
| --- | --- | --- |
| 前端框架 | React  + TypeScript + Vite | 构建用户界面 |
| 后端框架 | FastAPI + uvicorn | 提供 HTTP 接口 |
| AI 编排 | LangGraph | 把 AI 任务拆成图来执行 |
| LLM 接入 | LangChain（langchain-openai / langchain-anthropic） | 统一调用各家 AI 模型 |
| 向量存储 | Milvus Lite → 可扩展至 Milvus | 存储和检索知识库向量 |
| 关系存储 | SQLite → 可扩展至 MySQL / PostgreSQL | 存储用户、会话、消息等结构化数据 |
| 文件解析 | pypdf + python-docx | 从 PDF 和 DOCX 里提取文字 |
| 认证 | JWT（PyJWT）+ bcrypt | 登录鉴权和密码加密 |
| 流式传输 | SSE（Server-Sent Events） | 实现打字机效果 |
| 配置管理 | pydantic-settings | 从 .env 文件读取配置 |

这里要重点介绍的是 offer-agent 独有的三项核心技术：

- 数据库：SQLite，零依赖的单文件数据库

- AI 编排：LangGraph，有状态、多步骤的 LLM 工作流框架

- 向量存储：Milvus Lite，嵌入式向量数据库，用于 RAG 知识检索

为什么要选这三个，它们各自解决了什么问题，优势在哪里。下篇文章将逐一展开讲解。
