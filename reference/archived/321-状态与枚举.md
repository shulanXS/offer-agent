#### 会话状态机

面试会话（interview_sessions）有三个状态，流转是单向的，不可逆。

##### 状态定义

preparing（准备中）

会话创建后的初始状态。此时 plan_graph 已执行完毕，4道题已生成，等待用户确认开始。用户可以在此状态查看题目预览，也可以返回调整。

active（面试中）

用户确认开始后进入此状态。interview_graph 在此状态处理用户的每次回答，决定追问或推进下一题。只有此状态的会话可以接受 reply 请求。4道题全部完成后调用 finish 接口触发评分。

completed（已完成）

面试结束的终态。通过两个路径进入：第一，4题全部完成后调用 finish 接口，评分完成后自动切换；第二，用户调用 finish 接口手动结束。进入此状态后会话冻结，不再接受任何修改操作。

##### 状态流转表

| 当前状态 | 触发操作 | 目标状态 | 说明 |
| --- | --- | --- | --- |
| —— | POST /interviews/stream | preparing | 创建会话，扣减配额，生成题目 |
| preparing | POST /{id}/activate | active | 用户确认开始面试 |
| active | POST /{id}/reply/stream | active | 追问或下一题 |
| active | POST /{id}/reply/stream | completed | 最后一题答完，本次 reply 内评分 |
| active | POST /finish | completed | 主动结束面试并评分 |
| completed | —— | —— | 终态，不再流转 |

#### ErrorCode 枚举

所有错误码使用大写下划线格式，在错误响应的 code 字段中返回。

##### 认证与权限类

| 错误码 | HTTP 状态码 | 含义 |
| --- | --- | --- |
| AUTH_REQUIRED | 401 | Token 缺失或无效 |
| AUTH_INVALID | 401 | Token 格式无效或已过期 |
| INVALID_CREDENTIALS | 401 | 用户名不存在或密码错误 |
| USER_NOT_FOUND | 404 | 用户不存在 |
| USERNAME_EXISTS | 409 | 注册时用户名已被使用 |

##### 资源类

| 错误码 | HTTP 状态码 | 含义 |
| --- | --- | --- |
| RESUME_NOT_FOUND | 404 | 简历不存在，或不属于当前用户 |
| RESUME_TEXT_TOO_SHORT | 400 | 简历文本过短（<20字符） |
| RESUME_FILE_TYPE_UNSUPPORTED | 415 | 文件格式不在支持列表内 |
| SESSION_NOT_FOUND | 404 | 面试会话不存在，或不属于当前用户 |
| SESSION_ALREADY_COMPLETED | 409 | 会话已结束 |
| SESSION_NOT_ACTIVE | 409 | 会话不在 active 状态 |

##### 文件处理类

| 错误码 | HTTP 状态码 | 含义 |
| --- | --- | --- |
| RESUME_PARSE_FAILED | 422 | 简历文本提取失败，或 LLM 结构化解析返回非法结构 |

##### 业务逻辑类

|  |  |  |
| --- | --- | --- |
|  |  |  |
|  |  |  |
| VALIDATION_ERROR | 422 | 请求参数格式不合法，通常由 Pydantic 校验失败触发 |

##### 系统与 LLM 类

| 错误码 | HTTP 状态码 | 含义 |
| --- | --- | --- |
| MODEL_CONFIG_INVALID | 500 | 模型配置错误（如 API Key 无效） |
| INTERVIEW_BOOTSTRAP_FAILED | 502 | bootstrap 阶段题目生成异常 |
| INTERVIEW_REPLY_FAILED | 502 | 面试追问生成失败 |
| INTERVIEW_EVALUATION_FAILED | 502 | 面试评估生成失败 |
| INTERNAL_ERROR | 500 | 未预期的服务端异常 |

共 20 个错误码。

}

#### 消息角色枚举

用于 messages 表的 role 字段和 LangGraph 消息上下文。

| 枚举值 | 含义 |
| --- | --- |
| user | 用户发送的消息，即面试者的回答 |
| assistant | AI 面试官发送的消息，含题目、追问和过渡语 |

#### 难度等级枚举

用于 interview_sessions 表的 difficulty_level 字段，在创建面试时由用户选择。

| 枚举值 | 说明 |
| --- | --- |
| 入门 | 适合应届生或转行候选人。题目聚焦基础概念和常见场景，追问深度较浅。 |
| 进阶 | 适合 2-5 年经验候选人。题目涉及系统设计和项目决策，追问会要求展开原理。 |
| 挑战 | 适合高级工程师或架构师。题目深入架构权衡和复杂场景，追问会挑战边界情况。 |

说明： 难度等级影响 plan_graph 的 prompt 构造。不同难度下，LLM 生成题目时的指导方向不同，入门偏"是什么"，进阶偏"为什么和怎么做"，挑战偏"如果...你怎么设计"。
