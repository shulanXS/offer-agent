#### 第一步：用 AI 搭建前端骨架

搭建核心是明确技术栈约束和文件职责，以此生成规范目录与基础代码。

给 AI 的提示词参考：

````
用 Vite + React 19 + TypeScript 搭建 offer-agent 前端骨架。

约束：
- 不使用任何 UI 组件库（无 shadcn、无 antd、无 MUI）
- 不使用 CSS 框架（无 Tailwind）
- 样式集中在 App.css 和 index.css，手写 CSS 变量和布局

目录结构：
src/
  api.ts              # 所有后端请求的封装，含 SSE 消费
  App.tsx             # 主工作台：登录、视图切换、会话状态
  App.css             # 工作台布局与组件样式
  index.css           # 全局 reset
  types.ts            # TypeScript 类型定义
  constants.ts        # 默认值、状态文案
  components/
    PreparingStage.tsx        # 题目预览（preparing）
    InterviewSessionView.tsx  # 正式答题（session）
    EvaluationView.tsx        # 评分结果（evaluation）
    ResumePreviewPanel.tsx    # 简历侧栏预览
    ConfirmDialog.tsx           # 确认弹窗

主状态机设计：App.tsx 用 activeView 字符串切换五个工作区视图，
currentSession、selectedResumeId 等独立 state 承载业务数据。
````

AI 生成骨架后，还需要在 types.ts 完善面试会话、流式事件、简历相关实体类型，补齐业务所需 TS 约束。

#### 第二步：用 AI 设计工作台布局

完成页面整体布局与基础样式，采用侧边栏 + 主内容区经典结构，用 Flex 布局和 CSS 变量统一视觉风格。同时搭建核心视图路由，划分简历管理、面试答题、评分等五大页面，实现点击会话自动跳转对应视图的基础能力。

给 AI 看的原型图：

````
┌──────────────┬─────────────────────────────┐
│  侧边栏       │                              │
│  额度 / 导航  │    主内容区                   │
│  ──────────  │    (根据 activeView 切换)     │
│  简历列表     │                              │
│  会话历史     │                              │
└──────────────┴─────────────────────────────┘
````

提示词：

````
实现工作台布局：左侧边栏 + 右侧主内容区。
要求：
侧边栏固定宽度，主内容区 flex:1 自适应。
使用 Flex 布局，不使用 Grid。
在 :root 定义 CSS 变量：颜色、间距、圆角。
风格：简洁灰白 + 蓝色主色。
登录页与工作台共用外层容器。

同时实现 5 种视图切换：
简历管理、新建面试、题目预览、答题中、评分结果。
使用联合类型定义视图状态。
useState 管理：当前视图、会话、选中简历ID、选中会话ID。
主区域条件渲染对应组件。
侧边栏展示会话历史，点击跳转对应视图。
````

生成后，核对 CSS 变量配色、间距是否符合预期；测试视图切换、侧边栏会话点击跳转是否正常。

#### 第三步：实现 SSE 消费

这一步只做数据流：实现 SSE 流式读取、解析、事件分发。 因为需要携带 Token 鉴权，所以使用 fetch + ReadableStream。 目标：把后端推送的流事件，稳定解析并传递给前端状态。

给 AI 的提示词

````
在 api.ts 实现 SSE 流式消费函数：
使用 fetch + ReadableStream，不使用 EventSource。
解析标准 event/data 格式流数据。
包含状态码校验、异常处理、流读取、文本解码、数据分块。
通过回调函数向外抛出事件与数据。

在 App.tsx 实现事件处理函数 handleStreamEvent：
处理 session、message_start、delta、message_end、evaluation、done 事件。
根据事件类型更新对应状态：
- session：更新会话信息与题目
- message_start / delta / message_end：处理流式消息
- evaluation：更新评分结果
- done：刷新会话状态
创建面试、提交回答共用这套事件处理逻辑。
````

生成后测试流是否能正常接收、事件是否正确分发、无报错、无卡顿。

#### 第四步：实现乐观 UI

乐观 UI 的核心思想是：不等服务器响应，先更新本地状态，让用户感觉操作立刻生效了。对于面试场景，用户发送回答后，如果白屏等待，体验很差。

这一步基于已实现的 SSE 事件，添加乐观 UI，让用户操作秒反馈。 核心：提交回答后先本地渲染 UI，不等后端返回，大幅提升流畅度。

给 AI 的提示词

````
在 App.tsx 实现答题提交的乐观 UI 交互：
用户发送回答后，立即本地渲染用户消息。
显示临时的“思考中”加载动画。
收到 SSE 的 message_start 事件后，移除加载动画。
通过 delta 事件逐字渲染AI回复，实现打字机效果。
请求异常时自动清理临时状态并展示错误提示。
结束面试使用普通JSON接口，加载完成后切换到评分视图。
````

生成后测试提交回答是否即时响应、打字机是否流畅、异常场景是否正常兜底。

#### 第五步：会话状态恢复

浏览器刷新后 React 内存状态会丢失，这一步通过 localStorage 缓存登录令牌、会话 ID，实现刷新免登录、自动恢复会话，同时增加登录态校验。

给 AI 的提示词

````
使用 localStorage 持久化：
用户 token
当前会话ID
状态变化时自动同步到本地存储。
页面刷新后从本地读取并恢复状态。
根据会话状态自动跳转到对应页面。
token 失效则清空缓存并返回登录页。
````

生成后多次刷新页面，验证登录态、选中会话是否正常保留。

#### 第六步：联调验证

前后端都跑起来后，按以下顺序验证完整流程。

先在本地同时启动前后端：

````
# 后端（8000 端口）
cd backend && ./start.sh

# 前端（5173 端口）
cd frontend && npm run dev
````

前端需要在 vite.config.ts 配置开发代理，把 /api 请求转发到后端。后端路由本身带 /api 前缀，proxy 里不需要 rewrite：

````
// vite.config.ts
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true,
      },
    },
  },
});
````
