# 中期记忆：工作记忆与考察进度

目录路径：实战项目 / AI面试智能体 / V2 版本优化 / 四大优化点 / Agent 记忆体系：短期、中期和长期记忆 / 中期记忆：工作记忆与考察进度

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/A7ehwFwTiignMVkx51Pcyrq5nne)

短期记忆让 Agent 知道「这道题聊到了哪」。但光有最近几条消息，有一件事还是做不到：判断候选人到底有没有回答到点上，以及整场面试里还差哪些东西没有考察到。

短期记忆的职责是对话上下文，中期记忆的职责是考察进度。两者的区别是：短期记忆是自然语言的消息列表，Agent 每次用它时都要重新理解一遍；中期记忆是结构化的证据积累，Agent 可以直接读取「哪些 plan 信号已经被覆盖、哪些还没有」，不需要从消息里重新推理。

#### 中期记忆存什么

中期记忆存在 working_memory 里，每轮回答后增量更新，不重写：

````
# offer-agent/backend/app/services/interview/memory/schema.py — empty_working_memory() 结构
{
    "schema_version": 1,
    "claims": [], # 候选人自述观点，暂时没有原话佐证
    "evidence": [], # 带原文引用的有效作答证据，供决策、评估环节读取
    "risks": [], # 对话中识别到的潜在风险点
    "contradictions": [], # 前后回答存在冲突的记录
    "missing_information": [], # 当前还未收集到的考察要点
    "covered_topics": [], # 已经完整沟通完毕的主题
    "uncovered_topics": [], # 还未开始沟通的主题
}

````

各字段作用区分清晰：

- evidence：带有候选人原话引用的有效证据，绑定匹配到的考察关键词，关键词必须和面试方案预设的考察原文完全对应；

- claims：候选人提出的观点，但暂时没有足够原话支撑，待后续验证；

- missing_information：通过「全部预设考察点 - 已收集完成的考察点」固定计算得出，完全由代码运算，不是大模型生成。

#### 结构化证据从哪里来

用户每提交一轮回答，LangGraph 流程图里的 extract_evidence 节点会调用证据提取工具，从本轮回答中解析出结构化数据。

举个实际例子， 候选人回答：「我负责订单服务的整体架构设计，包括从单体拆成微服务，但当时时间比较紧，主要就是把功能拆出去，具体的数据指标没有特别关注。」

工具会从这段话里提取出标准化数据：

````
# offer-agent/backend/app/agent/interview/nodes/extract_evidence.py — 校验通过后的 extraction 示例
extraction = {
    "answer_quality": "partial",
    "claims": [{
        "topic_id": "topic-2",
        "content": "负责订单服务架构设计",
        "status": "unverified", # 仅自述，暂无完整证据支撑
        "probe_hint": "probe_ownership",
    }],
    "evidence": [{
        "topic_id": "topic-2",
        "matched_signal": "个人贡献可量化",
        "polarity": "negative", # 负向匹配，候选人未提供相关信息
        "quote": "具体的数据指标没有特别关注",
        "strength": 0.6,
        "rationale": "候选人主动表示没有关注指标，负向覆盖该信号",
    }],
    "missing_information": ["结果指标", "备选方案"],
    "risks": [],
    "potential_contradictions": [],
}
````

提取环节有两条硬性校验规则，不满足则直接丢弃本条提取数据，不存入工作记忆：

1. quote 原文片段，必须取自候选人本轮回答，不允许大模型自行改写、编造；

2. matched_signal 匹配关键词，必须完全沿用面试方案里预设的考察点，不能由大模型自创描述。

#### 工作记忆如何增量更新

提取完成后，merge_working_memory 节点把新证据合并进现有的工作记忆，不是替换：

````
# offer-agent/backend/app/services/interview/memory/merge.py（节选）
def merge_extraction_into_working_memory(...):
    # 在现有 working_memory 上增量合并，非整表替换
    merged = copy.deepcopy(base)
    merged["claims"] = _merge_claims(existing_claims, new_claims, stats)
    merged["evidence"] = _merge_evidence(existing_evidence, new_evidence, stats)

    # 每次 merge 后重算缺口与主题覆盖，保证与 plan 对齐
    merged["missing_information"] = recompute_missing_information(
        plan_json=plan_json, working_memory=merged
    )
    merged["covered_topics"], merged["uncovered_topics"] = recompute_topic_coverage(...)
````

missing_information 完全依靠代码固定计算：每次合并完成，系统自动用面试方案全部考察点，减去已有充足证据支撑的要点，算出当前还缺少哪些信息。全程不受大模型输出影响，不会出现模型凭空新增方案外考察点的问题。

#### 工作记忆如何进入 Decide

有了标准化工作记忆，Decide 决策节点不再依靠大模型主观判断，而是基于明确的信息缺口生成追问。 组装提示词时，会直接注入三类结构化数据：已收集完毕的考察点、待补充的信息缺口、近期关键证据摘要。

````
# offer-agent/backend/app/agent/interview/decide.py（节选）
# memory_context 来自 merge 后的 working_memory，经 Observe 注入 Prompt
prompt = DECIDE_PROMPT.format(
    covered_signals=format_covered_signals(memory_context),
    missing_information=format_missing_information(memory_context),
    recent_evidence_summary=format_recent_evidence_summary(memory_context),
    ...
)
````

仍以订单服务拆分为例，merge 完成后，memory_context 注入 DECIDE_PROMPT，LLM 实际看到的是下面这样：

LLM 据此返回结构化决策 JSON，例如：

````
{
  "action": "probe_metric",
  "target_topic_id": "topic-2",
  "reason": "候选人尚未给出可量化的结果指标",
  "expected_information": ["结果指标"],
  "should_change_topic": false
}
````

这段 JSON 给 Act 用，不直接展示给候选人。

LLM 挂掉时，规则降级也受益于此。规则代码可以从 missing_information 里取第一个未覆盖的 signal，直接映射到对应的下一步追问，而不是靠主题名称猜测该追什么。

#### 矛盾检测：只标记，不定罪

工作记忆还有一个专门处理矛盾的机制。每次合并数据时，会对比新提取的观点、证据和历史记录。如果出现同一考察点同时存在正反两类证据，或是前后自述内容互相冲突，就会生成一条矛盾记录存入 contradictions。

这里有一条关键设计：系统只标记存在待核实冲突，不会直接判定候选人撒谎、造假。专门通过清洗函数过滤定性负面词汇，统一替换成中性描述「待核实」。

````
# offer-agent/backend/app/services/interview/memory/contradictions.py
# 矛盾描述禁止下定论性词汇，统一替换为「待核实」
FORBIDDEN_CONCLUSION_WORDS = ("撒谎", "说谎", "造假", "欺骗", "虚假陈述")

def sanitize_contradiction_description(text: str) -> str:
    cleaned = str(text or "").strip()
    for word in FORBIDDEN_CONCLUSION_WORDS:
        cleaned = cleaned.replace(word, "待核实")

    # 清洗后为空 → 返回默认文案
    if not cleaned:
        return "前后表述待核实"
    # ...
````

检测到未核实冲突后，Decide 最多只会发起一轮验证式追问，冲突真伪交由候选人后续回答和新一轮证据提取判断，系统不会单方面直接下负面结论。

整场面试结束后，工作记忆会通过 project_evaluation_memory 函数，按主题规整为标准化证据集合，提供给评估节点使用，该部分会在评估体系专题详细讲解。

#### 整体流转路径

→ Decide（covered_signals、missing_information、recent_evidence_summary、pending_contradictions）

→   Act（经 decision 间接使用）
