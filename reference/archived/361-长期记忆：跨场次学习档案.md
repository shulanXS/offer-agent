[原页面](https://acn2lw4rwc26.feishu.cn/wiki/TgBiwWCamim6VIkjkl1cHOr6neU)

短期记忆和中期记忆都在一场面试的范围内工作。它们在面试结束后就完成了使命，不再参与后续的事情。

长期记忆要解决的是另一类问题：候选人练了几次，哪些薄弱点反复出现？

比如某个候选人在「项目结果量化」这个信号上，连续三场模拟面试都没有有效覆盖。这不是本场能看到的信息，只有跨场次聚合之后才会浮现。

#### 长期记忆能做什么

长期记忆可以从多个角度帮助候选人改进：

- 练习推荐：候选人准备下一场练习时，看到「你在结果量化上已经连续 3 场没有覆盖，建议本次重点准备」。候选人根据历史薄弱点有针对性地备战，而不是每次都从头练。

![页面图片](../assets/361-a55d2c0bbe654e98.png)

- 跨场次对比：评估报告里展示本场和上一场相比，哪些信号进步了、哪些仍然薄弱。候选人能看到自己的提升轨迹，而不是每场独立打分看不到变化。

![页面图片](../assets/361-b836d34d0504ec37.png)

- 趋势分析：多场下来，某个维度是在稳步改善还是反复波动？趋势比单场得分更能反映候选人的真实成长曲线。

- 薄弱点预警：如果某个信号在近期三场都没有改善，可以触发更强的推荐提示，提醒候选人这个方向可能需要专项训练。

#### 数据怎么聚合

每场面试全部评估完成后，系统会调用 record_session_outcome，把本场完整答题、得分、缺口信息打包生成一份本场结果快照

````
# offer-agent/backend/app/services/learning/aggregate.py — build_outcome_snapshot 输出（节选）
outcome_snapshot = {
    "session_id": session_id,
    "completed_at": "...",
    "topics": {
        "topic-1": {
            "topic_id": "topic-1", 
            "topic_dimension": "项目经历真实性验证", # 取自面试方案的主题分类
            "status": "partially_verified", # 取自本场评估结果
            "score": 3,
            "discussed": True,  # 是否和候选人聊过该主题
            "covered_signals": ["个人贡献"], # 本场答到位的考察点
            "missing_signals": ["结果指标", "备选方案"], # 本场缺失的考察点
        }
    }
}
````

数据聚合的分组维度是：用户 ID + 简历 ID + 目标岗位 + 面试类型

更换简历、区分校招 / 社招、更换求职岗位，都会生成独立档案。设计逻辑很简单：不同求职方向的考察重点不一样，短板没有参考对比意义，不能混在一起统计。

聚合函数 aggregate_profile 会遍历该候选人所有场次快照，统计每个考察点多次缺失的次数。只要同一个考察点在两场及以上练习里都属于缺失项，就会被判定为跨场重复薄弱点。

````
# offer-agent/backend/app/services/learning/aggregate.py（节选）
from app.services.learning.schema import REPEAT_WEAK_THRESHOLD

signal_stats: dict[str, dict] = {}
for outcome in ordered:
    for topic_data in topics.values():
        for signal in topic_data.get("missing_signals") or []:
            signal_stats[signal]["missing_count"] += 1

# 累计 missing 次数 ≥ 阈值（默认 2）→ 判定为跨场薄弱点
repeat_weak = [
    signal for signal, stats in signal_stats.items()
    if stats["missing_count"] >= REPEAT_WEAK_THRESHOLD
]
````

聚合是完全确定性的，没有 LLM 参与。聚合的依据是每场的 missing_signals，这些数据已经是结构化的，不需要 LLM 来理解；而且确定性代码可以单独测试，不依赖模型输出稳定性。

#### 为什么长期记忆不能进面试流程

这是长期记忆最关键的设计约束。 假设面试中途读取历史档案，知晓候选人上次某块内容答得不好，会严重破坏本场评估公平性：

1. 候选人本场该点回答十分完整，但历史低分记录拉低本场评分；

2. 本场完全没问到该主题，却因历史短板被标记弱项。

V2 的代码层面有明确的边界：decide.py、act.py、extract_evidence 节点，都不读取 learning_profiles 表；评估阶段的评分主路径消费的是当场的 evidence_by_topic，也不读档案。

长期记忆只在练习推荐和评估报告里的「与上一场对比」模块里被读取，这两个场景候选人都能清楚感知到。
