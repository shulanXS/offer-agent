# 三态与评分：不确定性也是信息

目录路径：实战项目 / AI面试智能体 / V2 版本优化 / 四大优化点 / 评估体系：证据链、置信度与可解释评分 / 三态与评分：不确定性也是信息

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/URy7wJm4siIDXOkuno2cFftUnCf)

上一篇讲了 Evaluation Agent 消费结构化证据而不是重读对话。有了证据，接下来的问题是：怎么从证据推出分数？

V2 的评分设计里有一个核心决定：引入三态，而不是直接给分。在分数之前，先确定这个主题处于哪个状态。

#### 三态的定义

每个主题的评估结果，首先被推导成三种状态之一：

- 已验证（verified）：有充分的正向证据，且 plan_json 的 expected_signals 基本被覆盖。不只是「聊到了」，而是有具体的 quote 支撑了关键信号。

- 部分验证（partially_verified）：有证据，有覆盖，但不够完整。比如 plan_json 有 3 个期望信号，只有 1 个被有效覆盖，或者有证据但强度不够高。

- 未验证（unverified）：没有足够的正向证据，也没有完成该主题。这个主题要么没有考到，要么候选人说的内容没有触及期望信号。

代码示例：

````
# offer-agent/backend/app/services/interview_evaluation/competencies.py — _derive_status（节选）
def _derive_status(*, topic_id, evidence, covered, expected, completed_topic_ids):
    strong_evidence = _strong_evidence(evidence)

    # 主题没聊完 且 没有强 evidence → 未验证
    if not strong_evidence and topic_id not in completed_topic_ids:
        return "unverified"

    if expected:
        # 期望信号全部覆盖 → 已验证
        if covered and all(signal in covered for signal in expected):
            return "verified"
        # 有部分覆盖或强 evidence → 部分验证
        if covered or strong_evidence:
            return "partially_verified"
        return "unverified"

    # plan 未配置 expected_signals 时的兜底
    if strong_evidence:
        # 强 evidence ≥ 2 条 → verified，否则 partially_verified
        return "verified" if len(strong_evidence) >= 2 else "partially_verified"
    return "unverified"
````

#### 未验证不给分

这是评分设计里最重要的原则：未验证主题不给确定分数。

score 字段在 status == "unverified" 时直接返回 None。前端展示时，unverified 的主题不会出现分数，也不会被写成「不符合」或「表现差」，而是展示为「未验证」，说明本场没有机会考到这个方向，或者没有足够信息来评判。

为什么？因为缺少证据不等于能力差。一场 45 分钟的面试，最多覆盖 4 到 5 个主题，每个主题 2 到 3 轮。计划里某个主题没有充分展开，可能是时间不够，可能是候选人的回答让面试官提前切题，可能是这个主题本来就是可选的。把「没考到」解读成「不行」，是不公平的推断。

````
# offer-agent/backend/app/services/interview_evaluation/competencies.py — _derive_score（节选）
def _derive_score(*, status, evidence, covered, expected):
    # 未验证 → 不给确定分数（缺少证据 ≠ 能力差）
    if status == "unverified":
        return None

    coverage_ratio = len(covered) / len(expected) if expected else ...
    negative_count = sum(1 for e in evidence if e.get("polarity") == "negative")
    # ...
````

#### 分数怎么算

V2 的分数体系分两层：

| 层级 | 刻度 | 谁有 | 前端展示 |
| --- | --- | --- | --- |
| 单主题 | 1–5 整数 | 仅 verified / partially_verified | 各维度 Tab 上的状态标签（表现较好 / 有亮点待加强 / 讨论不足），不单独显示 1–5 数字 |
| 综合分 | 0–100 | 至少有一个主题有分 | 评估页顶部圆环 |

为什么用 1–5，而不是让 LLM 直接打百分制？

- 一是量表形式。1–5 是面试 rubric、绩效评估里常见的李克特刻度：1–2 明显不足，3 基本到位，4–5 较好。每个 plan 主题独立打分，刻度短、好解释；页面再统一映射成 0–100，候选人只看一个综合分。

- 二是算分方式。V2 用确定性公式：输入是 evidence 的覆盖率、强度、正负向条数，输出是 1–5 整数。同样 evidence 跑两次结果一样，每个加减项都能追溯到 quote。

##### 单主题算分

已验证的基础分从 3.4 （表示基本到位）开始，加上信号覆盖率和平均证据强度的加成，减去负向证据的惩罚：

````
# offer-agent/backend/app/services/interview_evaluation/competencies.py — _derive_score（节选）
# verified：基础分 3.4 起，负向 evidence 轻惩罚
if status == "verified":
    base = 3.4 + coverage_ratio * 1.0 + avg_strength * 0.6
    base -= negative_count * 0.35
````

部分验证的计分更保守，起点从 1.6 （表示明显不足）开始，正向证据的权重更高，负向证据的惩罚也更重：

````
# offer-agent/backend/app/services/interview_evaluation/competencies.py — _derive_score（节选）
else:
    # 没有任何正向 evidence → 起点更低
    if positive_count == 0:
        base = 1.0 + coverage_ratio * 0.35 + avg_strength * 0.12
    else:
        base = 1.6 + coverage_ratio * 1.15 + positive_strength * 0.55
    base -= negative_count * 0.75

    # 负向多于正向 → 额外扣分
    if negative_count > positive_count:
        base -= 0.45
    # 只有负向、无正向 → 分数封顶
    if negative_count >= 1 and positive_count == 0:
        base = min(base, 1.35)
````

扣分不能凭主观感觉，必须要有实打实的负面原话作为依据。每一段候选人的发言，都会由模型标记这段内容的强弱程度和正负倾向。

后续出评测报告时，候选人能直接看到对应的原话，清楚自己哪句话拉低了分数，扣分理由一目了然。

##### 综合分的计算

综合分是对有分数的主题做简单平均，再映射到 0–100，展示在评估页顶部圆环：

````
# offer-agent/backend/app/services/interview_evaluation/aggregate.py — compute_overall_score
def compute_overall_score(competencies):
    # 只取有 score 的主题；unverified（score=None）不参与平均
    scores = [item["score"] for item in competencies if item.get("score") is not None]

    # 全部未验证 → 无综合分
    if not scores:
        return None
    average = sum(scores) / len(scores)
    return int(round(average / 5 * 100))
````

举个例子：面试一共设置 5 个考察方向，其中只有 4 个产出有效得分，分数分别为 2、3、3、4，剩余 1 个话题全程没展开、无法判定。 总分只计算有结果的 4 项：(2+3+3+4)÷4÷5×100 = 60

#### 置信度是什么

同样都是3分的考察维度，背后支撑的信息完整度差别很大。

比如一个维度攒了5条证据，覆盖了该板块全部考察要点；另一个维度只提取到1条证据，仅命中1个考察点，两份3分的可信度完全不在一个水平。

针对这个问题，V2给每项能力新增了0～1区间的置信度分数。这个数值会综合三条指标核算：证据总条数、考察要点覆盖比例、每条证据的平均支撑力度。

````
# offer-agent/backend/app/services/interview_evaluation/competencies.py — _derive_confidence（节选）
def _derive_confidence(*, status, evidence, covered_count, expected_count):
    # 未验证 → 置信度上限低（证据少也不强行拉高）
    if status == "unverified":
        return round(min(0.4, 0.2 + len(evidence) * 0.05), 2)

    coverage_ratio = covered_count / expected_count if expected_count else ...
    value = 0.35 + coverage_ratio * 0.35 + avg_strength * 0.25

    # verified 额外加一点权重
    if status == "verified":
        value += 0.08
    return round(min(0.95, value), 2)
````

置信度反映「这个分数有多可靠」，写入报告的 overall_confidence 字段，不参与上面的综合分加权平均。候选人在报告里能感知到的，是某个主题「回答依据」里有多少条原文引用——证据越多，分数越可信。
