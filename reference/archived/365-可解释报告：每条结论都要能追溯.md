# 可解释报告：每条结论都要能追溯

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/To2nwx4cniRG2ZkHUP2cZm8Nnhf)

有了三态和分数，评估报告还需要解决最后一个问题：候选人凭什么相信这个结论。

一份「项目所有权：3 分，部分验证」的评估，如果候选人看不到依据，它和一个随机数字没有区别。V2 的报告设计目标是：每条结论都能追溯，候选人知道是哪句话触发了这个评价，知道哪些方向没有机会展示，也知道下次该练什么。

#### 候选人打开评估页，自上而下看到什么

评估页的模块顺序，就是证据链的展示顺序。下面按页面从上到下说明每块数据从哪来、如何可追溯。

##### 1.
概览：分数与覆盖状态

这里先给面试者建立清晰认知：标了「未评」不代表能力不行，只是本场对话没有足够内容支撑判断，而且这部分也不会拉低总分。

接着展示 0-100 分的综合得分，计分规则前面也提到过：只把有充足证据、完成打分的维度算进平均分，再换算成百分制。 旁边会标注每个考察主题的三种状态：完整验证、部分验证、完全没聊到。

![页面图片](../assets/365-916db9558e07b87a.png)

##### 2.
本次反馈：亮点与不足

页面里的「回答亮点」「主要不足」，是结合各主题复盘、维度得分自动生成的，顶多微调一下语句，不会重新翻找对话素材。 系统会依次遍历面试规划里所有考察主题，从证据库、维度评分里提取完整信息：

- 考察目标：面试前就定好的考核要求

- 做得好的地方：对话里正向支撑的原话证据

- 存在短板：没覆盖到的考察要点，加上负面反馈对应的原话

- 原话引用：候选人当时的完整回答

![页面图片](../assets/365-2909db98b5e8a080.png)

面试者看到的「这块内容有短板」，是对照预设考察要点客观对比出来的，不是 AI 凭主观感觉下的判断。

##### 3.
与上一场对比（有多场历史时）

本次反馈下方是 「与上一场对比」。这部分数据不会存到本场的评估结果里，页面会单独调用接口拉取长期记忆汇总的对比信息。

展示内容包括：已考察方向数量（上一场 vs 本场）、各维度进步/退步要点。页面也会清晰标注一句提示：该对比仅作历史参考，不会改动本次得分。本场所有维度打分，只依据本次对话收集到的证据，不会受过往面试记录影响、加分或扣分。

![页面图片](../assets/365-e0630605c300b832.png)

另外这个对比模块有展示条件：必须存在可跨场次对比的数据、且能提炼出对比要点才会显示。如果是第一次模拟面试，页面就不会出现这一板块。

##### 4.
练习建议：从缺口到下一轮

练习建议板块，会把这次面试没答到位的点做成能直接点的「再来练一次」卡片。

后端会读取各个能力得分、复盘里没覆盖到的考察要点，自动匹配预设好的练习分类，像项目深挖、技术基础、系统设计这几类。

````
# offer-agent/backend/app/services/interview_evaluation/practice_recommendations.py
FOCUS_TOPIC_OPTIONS = (
    "项目深挖", "技术基础", "系统设计", ...
)
````

前端再把缺失的考察要点写到卡片简介里，让人一眼看清自己缺了哪些内容。候选人点一下卡片就能新建面试，系统会自动填上要重点练习的方向，下一轮的面试规划就会针对性多考察这些内容。

整套流程就形成闭环了：本次面试收集证据找出短板 → 评估报告明确标出短板 → 下次面试专门围绕短板出题。全程不靠主观感觉判断，全部依据标准化记录的缺失考察点。

##### 5.
各维度评价：结论 + 回答依据

这是整份报告最容易看懂的溯源板块，每个考察主题单独分一块展示： 上方是该维度的综合评价，由固定规则生成，可简单润色文字；下方专门放「回答依据」，按对话顺序列出相关问答，全部来自之前存储好的证据和对话记录。

> 图片尚未保存：[在原页面查看](https://acn2lw4rwc26.feishu.cn/wiki/To2nwx4cniRG2ZkHUP2cZm8Nnhf)（图片标识：DAp7bRxpyoocptxEGPqcb1lunCb）

整条逻辑线一目了然：第几轮对话 → 候选人原话 → 匹配哪条考察要求 → 这段回答算加分还是减分项。之前提到负面回答会扣分，在这里都能找到对应的原文，不会只笼统一句「该部分表现不足」。

##### 6.
JD 要点验证

如果创建面试时填写了岗位 JD，页面底部会多出一块 JD 匹配校验内容。 系统不会通篇拆解 JD 全文，只筛选面试规划里标记和 JD 相关的考察主题做核对。

````
# offer-agent/backend/app/services/interview_evaluation/jd_match.py（节选）
jd_text = str(configuration.get("jd_text", "") or "").strip()
if not jd_text:
    return None

alignments = extract_plan_jd_alignments(plan_json)
for item in alignments:
    status, quotes, note = _classify_alignment(
        topic_id=str(item["topic_id"]),
        competency=competency_by_topic.get(str(item["topic_id"])),
        evidence_by_topic=evidence_by_topic,
    )
    # verified_aligned | verified_with_risk | unverified
````

判断逻辑和全局标准保持一致：完全没聊到的板块，不会直接判定「不符合 JD 需求」，缺少证据不等于能力不达标；如果某块能力存在风险，会附上对应的候选人原话，和分维度评价共用同一套证据。
