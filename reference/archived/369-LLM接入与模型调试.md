# LLM接入与模型调试

目录路径：实战项目 / AI面试智能体 / 常见问题排查指南 / LLM接入与模型调试

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/CJCYw8mHjizPEQkhuTFchELdnrs)

接上真实模型后，常见问题：Provider 和模型名不配、Key 未生效、超时、回复含思考过程。项目无 mock 模式——未配好 Provider 时调用会报错；各业务模块另有规则/模板降级。配置写在 backend/.env，改完须重启后端。详见 backend/LLM_README.md。

#### Provider 和 Model 没有配套

现象： 比如 Provider 改成 anthropic，模型名还写着 gpt-4o-mini，网关报模型不存在。

说明： LLM_PROVIDER（用哪家 API）和 LLM_MODEL（具体模型名）须成套填写，不能混用。

解决： 在 .env 成对配置，例如：

| LLM_PROVIDER | LLM_MODEL 示例 |
| --- | --- |
| openai | gpt-4o-mini、gpt-4o |
| anthropic / claude / claude_code | 按网关文档填写 |
| volcengine / ark / volc / huoshan | doubao-seed-1-6-flash-250715 等 |

#### LLM_PROVIDER 拼写错误

现象： 启动报 ValueError: 不支持的 LLM_PROVIDER。

说明： 大小写不敏感，但须在支持列表内，不支持 mock。

解决： 确认值为 openai、anthropic/claude/claude_code、volcengine/ark/volc/huoshan 之一。

#### 配置了 Key 仍报 MODEL_CONFIG_INVALID

现象： 生成计划、对话或评估时报 MODEL_CONFIG_INVALID，或日志里 LLM 调用失败。

排查：

1. Key 写在 backend/.env，不要只在终端临时 export

2. 改 .env 后重启后端

3. 按 Provider 填对应 Key：OPENAI_API_KEY、ANTHROPIC_API_KEY、VOLCENGINE_API_KEY

4. 用中转网关时，配 OPENAI_BASE_URL 或 ANTHROPIC_BASE_URL

#### LLM 返回内容含思考过程

现象： 面试官回复出现「让我分析一下…」等不该给候选人看的推理文字。

说明： 部分模型会在正文里夹杂推理。项目有过滤逻辑，新模型措辞可能还没覆盖到。

解决：

1. 查日志里原始 LLM 响应

2. 在 factory.py 的 _REASONING_MARKERS / _META_LINE_PATTERNS 补充特征词

3. Anthropic thinking 块已有单独过滤；多数情况是 text 块内混入了推理

#### 请求超时

现象： 报错含 timeout，或前端提示「请求超时」（慢接口默认最长约 300 秒）。

说明： 先区分「连不上」（Connection refused）和「真超时」。计划生成、单轮对话可能串行调多次模型，等得久不一定是 bug。流式首字晚见 05-流式输出排查。

排查：

1. 用 curl 测网关是否通畅、延迟多少

2. 可调大 LLM_TIMEOUT_SECONDS（默认 300）

3. 确认不是地址错、服务没起却被误判为超时

#### 中转 Base URL

说明： 不用官方地址、走第三方兼容网关时的配置。

解决：

- OpenAI 中转：OPENAI_BASE_URL + OPENAI_API_KEY

- Anthropic 中转：ANTHROPIC_BASE_URL（工厂默认加 Authorization: Bearer）；中转格式不同时改 factory.py 请求头

#### 快速验证 LLM 是否接通

在 backend/ 下（已配好 Provider 和 Key）：

````
# verify_llm.py
import sys
sys.path.insert(0, ".")

from app.llm.factory import create_llm_client

client = create_llm_client()
result = client.generate_text("你好，请回复 ok", operation_name="verify")
print(result)
````

````
cd backend && source .venv/bin/activate && python verify_llm.py
````

能通过说明 Key/网关正常；业务仍失败则查各 Agent 日志里的 trace_id，不必再查 Key。

#### 模型失败时各模块怎么兜底

| 模块 | LLM 失败时 |
| --- | --- |
| 简历解析 | 规则抽取 |
| 面试计划 | 本地岗位模板 |
| 面试对话 | 规则决策 + 模板话术 |
| 报告叙事 | 模板总结；分数仍由规则+证据计算 |

pytest 强制走降级路径，CI 不需要真实 Key。
