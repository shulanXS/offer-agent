# 面试对话与状态

目录路径：实战项目 / AI面试智能体 / 常见问题排查指南 / 面试对话与状态

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/AW1Wwv2nTiomLwkOoAmcLt5Pnte)

计划确认后进入正式对话，由 Interview Agent（LangGraph + ODA）按锁定计划提问、追问、换题。查进度用 GET /api/interviews/{session_id}，看 status（大阶段）和 workflow_state（轮次等细节）。

#### 会话状态一览

|  |  |  |
| --- | --- | --- |
| planning / plan_ready | 计划未确认 | 换计划、确认计划 |
| plan_confirmed | 计划已锁定，未开场 | 开始面试 |
| active | 面试进行中 | 发回答、结束面试 |
| evaluating | 已结束，待出报告 | 生成评估（不能再对话） |
| completed | 报告已生成 | 查看报告 |

#### 无法开始面试（activate 失败）

现象： 「请先确认并锁定面试计划」「尚未锁定可用计划」「面试额度不足」（INTERVIEW_QUOTA_EXHAUSTED）。

说明： 创建计划不扣额度；开始面试成功时扣 1 次。已结束（evaluating/completed）不能再开始。重复点开始不会重复插开场白。

排查：

1. 须先确认计划，status 为 plan_confirmed，且有 confirmed_plan_id

2. 额度不足：查账号剩余次数

3. 还在预览阶段就直接发回答也会失败（见下一节）

#### 发送回答无输出或 SESSION_NOT_ACTIVE

现象： 提交后空白；提示「请先开始正式面试」。

说明： 只有 status === active（已点开始面试）才能发回答。计划确认了但没点开始，或面试已结束，都会拒。

排查：

1. 确认已点「开始面试」且 status === active

2. 日志搜 Interview reply requested + trace_id

3. 有响应但页面不打字，查 05-流式输出

#### INTERVIEW_REPLY_IN_PROGRESS（重复提交）

现象： 连点发送被拒；提示上一条还在处理。

说明： 上一条回答处理完之前有加锁，须等 SSE done 事件后再发。

排查： 刷新后仍锁着，查会话详情看服务是否已清理陈旧锁。

#### 追问 / 切题不符合预期

现象： 单主题追问过多、整场超轮、或题目跑题像通用八股。

说明： 以下为代码强制边界；面试官只能按已锁定计划出题，不能现场发明新题。首问来自计划「开场首问」（可口语化，意图不变）。

| 规则 | 限制 |
| --- | --- |
| 整场时长 | 45 分钟（最后约 5 分钟收尾） |
| 用户回答总轮次 | ≤12 |
| 单主题回答次数 | ≤3 |
| 单主题追问次数 | ≤2 |

排查：

1. workflow_state：answer_round、topic_answer_rounds、topic_probe_count

2. 日志里 Decide 的 action：probe（追问）、advance（换题）、finish（结束）

3. 跑题：检查是否未读锁定计划而生成通用题

#### finish 与 evaluate 的区别

现象： 结束面试后评估页一直 loading。

说明： 结束和出报告是两步：finish 只把状态改为 evaluating（待评估）；evaluate 才算分、写报告，变为 completed。满 12 轮或超时自动结束同理。

| 接口 | 作用 |
| --- | --- |
| POST .../finish | 结束面试 → evaluating |
| POST .../evaluate | 生成报告 → completed |

排查：

1. finish 是否 200，status 是否 evaluating

2. 是否随后调用了 evaluate（前端一般在进评估页时触发）

3. evaluate 失败查 06-评估报告
