# 评估报告问题

目录路径：实战项目 / AI面试智能体 / 常见问题排查指南 / 评估报告问题

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/Im1DwuQwNi1lmJk9qe5cu1aWn3b)

分数由规则 + 面试过程中的结构化证据计算，大模型只润色文字总结（失败用模板），不用 LLM 直接拍分。出报告须两步：finish（结束 → evaluating）→ evaluate（生成 → completed）。

#### 结束面试后报告出不来

现象： 评估页空白或一直转圈。

说明： finish 只标记「待评估」，不会同步算报告。还须调 evaluate 才会算分、写引用、生成练习建议。面试还在进行中就调 evaluate 会报「尚未进入评估状态」。

排查：

1. finish 是否 200，status 是否 evaluating

2. 是否调用了 POST .../evaluate（前端一般在进评估页时触发）

3. 失败看 INTERVIEW_EVALUATION_FAILED + trace_id

4. 已 completed 且有报告时，重复 evaluate 应返回已有报告

#### 分数看起来不合理

说明：

- 能力项与计划主题一一对应

- 三态：已验证 / 部分验证 / 未验证——未验证不给分，也不能写成「不符合」

- 无保底分；负面证据多可落到最低档（1 分 / 20 分）

- 分数由规则推导，非 LLM 直出

排查：

1. workflow_state.working_memory 各主题下是否有证据

2. 未讨论的主题应为「未验证」，不是硬给低分

3. 报告 evidence_references 与工作记忆 quote 是否一致

#### 证据引用对不上原话

说明： 引用应来自工作记忆里的 quote，并关联问答轮次。证据缺失时可用 messages 补原文，但不能替代证据做主打分。

排查：

1. 引用是否来自工作记忆 quote 且带轮次

2. 消息 meta.topic_id 是否与计划主题一致

#### 面试记录列表状态不对

说明： 列表是 status 的人话翻译：plan_confirmed→未开始；active→进行中；evaluating→评估中；completed→已完成。偶发不一致时以详情为准。

排查： 刷新列表，或 GET /api/interviews/{id} 对照；列表会对卡住的 active 做纠偏。

#### 跨场次对比不显示

说明： 学习档案能力。首场无「上一场」；或上一场未成功 evaluate，档案无记录。

排查： 确保上一场走完 evaluate，且为同一简历档案（profile）；第二场结束后才有对比数据。
