# 流式输出排查

目录路径：实战项目 / AI面试智能体 / 常见问题排查指南 / 流式输出排查

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/IIUAwP0foi8udikTIFzcwuE2nmc)

只有发回答后的面试官回复走流式（SSE）：POST /api/interviews/{id}/reply/stream。以下不是流式，而是一次性等结果：

- 生成计划、开始面试（开场白）、结束面试、生成评估报告

#### 请求 pending 很久才有首字

现象： 发送后聊天区长时间空白，过一会儿才开始一个字一个字出来。

说明： 这是预期行为。后端先完整跑完本轮 Agent（边界检查 → 证据 → 决策 → 话术），拿到整段回复后再分片模拟打字，不是模型出一个字推一个字。慢通常因串行调模型，见 02-LLM。

排查： 确认请求最终 200 且有 SSE 数据；若只是慢，优先查模型延迟，不必改前端解析。

#### 请求非 200，完全没有流

现象： reply/stream 直接失败，响应里没有 event: 行。

说明： 常见错误码：SESSION_NOT_ACTIVE（未开始或已结束）、INTERVIEW_REPLY_IN_PROGRESS（上一条未处理完）、INTERVIEW_REPLY_FAILED（本轮处理失败）。

排查：

1. 看响应 message 和 code

2. 日志搜 INTERVIEW_REPLY_FAILED + trace_id

3. 模型失败应有规则降级；仍 500 查 Agent 日志。状态问题见 04-面试对话与状态

#### 收到 SSE 但页面不更新

现象： Network 里 Response 在增长，聊天窗口不动。

说明： 前端用 fetch + ReadableStream 解析 SSE（需 POST body，不能用 EventSource）。事件须按名解析：

````
event: progress → message_start → delta（多次）→ message_end → done
````

delta 数据形如 {"message_id":"...","delta":"字"}，不要用 token 等旧字段名。

排查：

1. 按 \n\n 切块，解析 event: 和 data:（见 consumeEventStream）

2. 批量 delta 可用打字机队列逐字显示
