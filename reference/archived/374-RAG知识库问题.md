# RAG知识库问题

目录路径：实战项目 / AI面试智能体 / 常见问题排查指南 / RAG知识库问题

[原页面](https://acn2lw4rwc26.feishu.cn/wiki/QDURwJOo7iKWv6ko6U7c8aKsnLh)

岗位知识库（RAG）在生成面试计划时从 knowledge/roles/ 检索相关段落，帮计划更贴岗位。对话和评估不查库。默认 RAG_ENABLED=false。详见 backend/RAG_README.md。

#### pymilvus 安装失败

现象： 安装 milvus-lite 相关包编译失败；导入 MilvusClient 报错。

解决：

````
# macOS
xcode-select --install

# Ubuntu / Debian
sudo apt-get install -y build-essential cmake
````

Apple Silicon 须 ARM 原生 Python（platform.machine() 为 arm64）。

````
python -c "from pymilvus import MilvusClient; print('ok')"
````

#### 启用了 RAG 但向量库是空的

现象： RAG_ENABLED=true，但计划内容和没开时差不多。

说明： 开关只表示「生成计划时会查库」；库空则检索为零，等于没用上。

解决：

````
cd backend
python3 scripts/index_role_knowledge.py
````

成功打印 Documents（文档数）、Chunks（切片数）、Dimension（向量维度）。start.sh 在库不存在时可能自动索引。

Chunks 为 0：检查 knowledge/roles/ 是否有对应岗位 md，target_role 能否映射到文件名。

#### Embedding 维度不匹配

现象： 切换 RAG_EMBEDDING_PROVIDER 后报维度错误。

说明： 不同嵌入模型向量长度不同，换 provider 须重建索引。

解决：

1. 同步改 RAG_EMBEDDING_PROVIDER 和 RAG_EMBEDDING_DIMENSION

2. 删除 data/milvus_lite.db

3. 重新跑索引脚本并重启后端

| Provider | 典型维度 |
| --- | --- |
| local（哈希，免 Key） | 256 |
| openai | 1536 |

openai 未配 Key 会报错，不会自动切 local。

#### 检索无命中

现象： 日志 Planning RAG returned no hits；计划内容很泛。

排查：

1. target_role 是否映射到 knowledge/roles/ 已有文件

2. 新 md 是否加入索引器角色映射表

3. local 嵌入靠词面匹配，措辞差太多命中率低 → 可改 openai 嵌入并重建索引

#### 知识文档分块过少

说明： 索引器按 markdown 的 ## 二级标题切章；无 ## 可能切成无效块。

解决： 参照 knowledge/README.md 和 knowledge/roles/ 示例改结构，再重新索引。

#### 与对话 LLM 的关系

说明： LLM_PROVIDER（对话）和 RAG_EMBEDDING_PROVIDER（向量）独立配置。对话用 anthropic、向量用 openai 时，须单独配 OPENAI_API_KEY。

常见组合：开发用 anthropic + local 向量；上线用 openai 对话 + openai 向量（一个 Key 两用）。
