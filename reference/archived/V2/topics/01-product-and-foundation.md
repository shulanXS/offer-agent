# 产品体验与新版基础

## 1. 文档状态

- 状态：**已完成**
- 对应路线图：阶段 0、阶段 1
- 唯一主专题：是

## 2. 改造目标

将旧工作台直接升级为新版 AI 面试官工作台。本分支不再维护 V1/V2 双入口，用户访问 `/` 即进入新版工作台。

本专题完成后，主工作台具备新版页面骨架、登录状态恢复、简历管理能力和后续面试配置入口；旧工作台入口、返回旧版入口和 `/v2` 双入口逻辑不再作为产品要求。

## 3. 本专题范围

### 负责

- 明确旧工作台替换边界
- 将 `/` 前端入口切换为新版工作台
- 复用现有登录身份、Token 存储和用户信息接口
- 复用现有简历列表、上传、删除和详情读取能力
- 建立新版页面框架、导航和占位页面
- 建立新版前端基础组件体系
- 确保刷新 `/` 和新版内部路由可以正常加载
- 清理或废弃 V1/V2 双入口切换逻辑

### 不负责

- 面试配置字段
- JD 上传和解析
- Planning、Interview、Evaluation Agent
- 新版面试会话数据表
- 旧工作台功能兼容

## 4. 依赖契约

- 复用现有认证 API、Token 存储方式和当前用户接口。
- 复用现有简历列表、上传、删除和详情接口；如后续需要调整响应结构，应在对应专题中明确。
- 向后续专题提供主工作台页面容器、登录状态和简历读取能力。
- 后续专题不得要求本专题预先创建面试业务表或 Agent。
- 旧 V1 工作台代码可以作为迁移参考，但不再作为必须兼容的产品入口。

### 旧能力处理边界

- 直接保留：认证 API、JWT Token、当前用户与额度、简历数据、简历上传/删除/详情 API、LLM Factory、配置与通用基础工具。
- 允许抽取：已经被新版工作台实际使用的前端组件、文件处理、错误处理和基础工具。
- 替换重构：旧 `App.tsx` 工作台业务状态、旧 `App.css` 样式、旧固定四题面试流程、旧面试会话和消息体验。
- 废弃或清理：`/v2` 双入口判断、V1 进入 V2、V2 返回 V1、`BrowserRouter basename="/v2"` 等并存逻辑。
- 验证要求：新版主入口、登录状态恢复、简历管理和前端生产构建必须通过。

## 5. 产品规则

### 5.1 入口

- `/`：新版 AI 面试官工作台。
- `/resumes`：我的简历。
- `/interviews/new`：创建面试占位页面，后续由专题 02 接入配置页。
- `/interviews`：面试记录占位页面，后续由专题 03/04 接入会话记录。
- 未登录用户访问新版工作台时展示登录入口或跳转到当前登录页，不依赖旧工作台承载登录。
- 登录后显示当前用户、剩余额度和简历管理入口。
- 不提供返回旧版入口。
- 不要求 `/v2` 路径继续可用；如短期保留，只能作为重定向到 `/` 的兼容路径。

### 5.2 初始页面

新版骨架阶段至少展示：

- `AI 面试官` 产品标识
- 当前用户和剩余额度
- “我的简历”入口，可上传、删除、读取和查看现有简历解析结果
- “创建面试”占位入口
- “面试记录”占位入口
- 当前阶段尚未开放功能的明确说明

### 5.3 替换规则

- 主入口继续使用 `frontend/src/App.tsx`，但其内容原地替换为新版工作台。
- 新版样式直接合并到 `frontend/src/App.css` 或更名后的主样式文件，不长期保留 `v2.css` 作为版本化样式。
- 已完成的 `frontend/src/v2/` 页面、组件、样式和工具可以作为迁移来源，但完成本专题后应合并回主工作台结构并删除 `frontend/src/v2/`。
- 完成本专题后不得保留 `/v2` 产品入口、V1/V2 切换逻辑、`BrowserRouter basename="/v2"`、V1 进入 V2 或 V2 返回 V1 入口。
- 后端删除 `/api/v2/healthz` 和 `backend/app/v2/`；健康检查仅保留主路径 `/healthz`。
- 旧面试业务可以在后续专题中被破坏性替换。

## 6. 技术设计

### 6.1 推荐前端结构

本专题完成后的主前端结构：

```text
frontend/src/
├── App.tsx                 # 新版工作台根组件
├── App.css                 # 新版主样式
├── main.tsx                # 直接渲染新版工作台
├── api.ts
├── types.ts
├── components/
│   └── ui/
├── pages/
├── utils/
└── constants.ts
```

`main.tsx` 继续渲染 `App`，但不再根据路径选择旧工作台或新版工作台。新版内部可以继续使用 `react-router-dom`，但 basename 应为 `/` 或不设置 basename。

`frontend/src/navigation.ts` 如只用于 V1/V2 切换，应删除。若后续仍需要应用内跳转工具，应重新定义为普通路由跳转能力。

认证、用户、简历列表、上传、删除和详情读取继续复用 `frontend/src/api.ts` 与 `frontend/src/types.ts`；只有出现新版专属接口时才新增对应 API 封装。

新版页面优先使用 shadcn/ui 的 `Button`、`Card`、`Input`、`Label`、`Badge`、`AlertDialog` 等基础组件。

首期路由：

```text
/
  -> /resumes
/resumes
  我的简历
/interviews/new
  创建面试占位
/interviews
  面试记录占位
```

### 6.2 推荐后端结构

删除旧双入口阶段新增的 `backend/app/v2/` 和 `/api/v2/healthz`。后续新版业务接口不使用 `/api/v2` 前缀；旧 `/api/interviews` 可以在专题 03/04 中被替换为新版面试接口。

### 6.3 API

健康检查继续使用：

```http
GET /healthz
```

简历继续使用现有：

```http
GET    /api/resumes
GET    /api/resumes/{resume_id}
POST   /api/resumes/extract
DELETE /api/resumes/{resume_id}
```

### 6.4 前端路径刷新

开发环境和生产部署必须支持直接访问或刷新 `/`、`/resumes`、`/interviews/new` 和 `/interviews` 后返回前端 `index.html`。若部署配置不在仓库中，需在实施记录中明确说明验证方式和外部配置要求。

## 7. 分步实施

### 小步 1：建立测试基线与替换边界

实现：

- 补充后端测试运行依赖和最小测试配置。
- 为健康检查、认证、简历读取或 V1 工作流（LLM 失败降级）增加最小基础测试。
- 记录旧工作台中可复用能力和将被替换的能力。

不实现：

- 新版页面和新版业务 API。

验证：

- `frontend` 执行生产构建通过。
- `backend` 测试命令能够运行。
- 基础能力测试通过。

完成条件：

- 后续替换主工作台前具备最小验证基线。

### 小步 2：将新版工作台挂到 `/`

实现：

- `main.tsx` 继续渲染 `App`。
- `App.tsx` 原地替换为新版工作台根组件。
- 新版内部路由从 `/` 管理，不再使用 `/v2` basename。
- 清理 V1/V2 前端内切换逻辑。
- 将 `frontend/src/v2/` 中已完成的页面、组件、样式和工具合并回主工作台结构，并删除 `frontend/src/v2/`。
- 新版页面展示 `AI 面试官` 标识和占位内容。

不实现：

- 登录复用、简历展示和新版面试业务接口。

前端验证：

- `/` 展示新版工作台。
- `/resumes` 展示新版简历页面占位。
- `/interviews/new` 和 `/interviews` 展示占位页面。
- 刷新上述路径可以正常加载。
- 页面不展示进入旧版或返回旧版入口。

完成条件：

- 新版主入口可以独立访问。

### 小步 3：登录状态恢复

实现：

- 新版工作台复用 Token 和现有当前用户 API。
- 登录后显示当前用户和额度。
- 未登录时展示登录入口或跳转到当前登录页。

不实现：

- 新版面试业务接口。

前端验证：

- 未登录访问 `/` 时可以进入登录流程。
- 登录后进入新版工作台。
- 刷新后可以恢复登录状态。

后端验证：

- `/healthz` 正常。
- 不再注册 `/api/v2/healthz`。

完成条件：

- 新版主入口和身份链路可用。

### 小步 4：接入现有简历读取与页面框架

实现：

- 新版工作台显示现有简历列表。
- 支持上传简历、删除简历和查看解析结果。
- 简历上传解析中时，仅正在解析的简历禁止查看结果和删除；其他已解析简历仍可查看结果。
- 建立新版导航和后续功能占位入口。
- 占位入口使用新版内部路由承载，不调用未实现 API。

不实现：

- 面试配置。

前端验证：

- 新版工作台能显示当前用户已有简历。
- 新版工作台能上传和删除简历，并复用现有简历接口。
- 点击“查看结果”可查看基础摘要。
- 上传解析中的简历不可查看结果、不可删除；已解析简历不受其他简历上传状态影响。
- `/interviews/new` 和 `/interviews` 展示占位页面，不触发未实现 API。

完成条件：

- 后续专题具备可接入的新版页面骨架。

## 8. 测试与验收

- `/` 展示新版工作台。
- 新版内部路由可访问并支持刷新。
- 登录状态可以恢复。
- 新版工作台可以读取现有简历。
- 新版工作台可以上传、删除和查看简历解析结果。
- 解析中的简历不可查看结果和删除，其他已解析简历仍可查看结果。
- 前端生产构建通过。
- 后端基础测试通过。

## 9. 质量、安全与降级

- 不复制或记录完整简历到新增日志。
- 健康接口不泄露配置、Key 或内部路径。
- 新版页面请求失败时显示明确错误。
- 不为了保留旧工作台而复制双份业务状态。

## 10. 停止条件

出现以下情况时停止本专题，不进入专题 02：

- `/` 新版主入口无法稳定加载。
- 登录态无法恢复且没有明确修复方案。
- 简历读取、上传或删除能力不可用。
- 新版页面仍依赖 V1/V2 双入口切换才能运行。
